# 이음 (IEUM)

신입 취업과 경력 이직을 준비하는 사람을 위한 개인 커리어 작업 공간입니다. 프로젝트와 실제 경험을 기록하고, 기업·공고별로 서류와 면접을 준비하며, 선택한 경험으로 포트폴리오 사이트를 만들 수 있습니다.

## 실행

Node.js **24 이상**이 필요합니다. 로컬 서버는 Node 내장 SQLite를, Vercel 배포는 Turso 원격 SQLite를 사용합니다.

```bash
npm ci
cp .env.example .env.local
# .env.local의 GROQ_API_KEY에 키 설정 (클라우드에서는 환경 비밀 바인딩 사용)
npm run dev
```

API 키는 서버에서만 사용합니다. 키 없이도 기록·서류 편집·포트폴리오 기능은 동작합니다. AI 기능은 키가 설정되어 있어야 합니다. 클라우드 비밀 프록시를 사용하므로 개발·운영 스크립트에 `NODE_USE_ENV_PROXY=1`을 설정했습니다.

```bash
npm run typecheck
npm test
npm run build
npm start
```

실제 브라우저 검증:

```bash
npx playwright install chromium
npm run test:e2e
```

브라우저 검증은 자체 개발 서버를 3100번 포트에서 시작합니다. Next 개발 서버가 이미 실행 중이면 먼저 종료하세요. 테스트용 기록은 `.data/e2e`에 별도로 저장됩니다. 가짜 관리자 계정은 이 로컬 테스트 DB에만 생성되며 운영 계정과 연결되지 않습니다. 클라우드에서는 `PLAYWRIGHT_BROWSERS_PATH=/workspace/.cache/ms-playwright`를 설치와 테스트 명령에 함께 지정합니다.

## 구현된 기능

- 처음 시작하는 7단계 준비 가이드와 사용 FAQ: 신입/경력·배경별 안내, 실제 기록에 따른 준비 현황
- 샘플 공간 체험과 개인 준비 프로필: 신입/경력, 전공 배경, 목표 직무
- 준비 대시보드, 체크리스트, 지원 진행 상태, 작업 공간 검색
- 프로젝트·연구·활동·업무 경험 정리와 공고별 경험 연결
- 짧은 답변 기반 AI 경험 초안: 근거 표시·보완 질문·항목별 선택 반영·직접 수정, 실패 시 입력 유지 및 AI 없는 작성 경로
- 희망기업·공고 등록, 입력 자료에 근거한 AI 기업 분석 및 경험 맞춤 분석
- 컬처핏 업무 환경 8문항, 잡핏 업무 선호 8문항, 조직 상황 6문항: 답변 근거·후속 질문·최근 10회 기록 비교·선택적인 AI 자기성찰
- 경험에 근거한 AI SWOT 분석 및 직접 수정
- 공고 없는 마스터 이력서·자소서·경력기술서와 공통 면접 질문·답변 보관함; 기업별 독립 복사
- 기업·공고별 이력서, 자소서, 경력기술서: AI 초안, 편집, 글자수, 저장 이력, 복사, 브라우저 인쇄/PDF
- 변경되지 않는 제출본과 제출 당시 프로젝트·공고 스냅샷
- 면접 예상 질문, 답변 라이브러리, 텍스트 연습, 피드백·후속 질문 및 연습 기록
- 프로젝트 선택·순서·공개용 제목/성과 편집, 포트폴리오 미리보기, 계정 기반 링크 게시·공개 해제
- 이메일·비밀번호 계정, 사용자별 서버 저장, 세션 쿠키
- 지정된 본인 계정의 관리자 모드: 공지 초안·미리보기·게시·수정·상단 고정·공개 해제·삭제, 방문자용 이음 소식
- 모바일 화면, 키보드 대화상자 탐색, 동작 줄이기 설정 지원

처음 표시되는 회사·공고·경험은 **샘플**입니다. 실제 채용 정보가 아닙니다. “내 공간 만들기”에서 샘플을 비우고 준비를 시작할 수 있습니다.

## 저장과 AI

로컬 개인 기록은 `.data/careermap.sqlite`에 저장됩니다. Vercel에서는 `TURSO_DATABASE_URL`과 `TURSO_AUTH_TOKEN`으로 영구 DB에 저장합니다. 배포 연결 절차는 [Vercel 배포 안내](docs/DEPLOYMENT.md)에 있습니다. `CAREERMAP_DATA_DIR`로 위치를 바꿀 수 있습니다. 임시 공간도 서버에 저장되며, 계정 생성 시 현재 기록을 유지합니다. 임시 공간에 다시 접근하려면 해당 브라우저의 세션 쿠키가 필요합니다.

작업 공간 수정은 revision을 사용해 다른 탭의 변경을 덮어쓰지 않습니다. 제출본은 서버에서도 수정·삭제를 거부합니다. 원본 경험을 수정해도 제출본과 이미 게시한 포트폴리오는 바뀌지 않습니다. 포트폴리오는 **다시 게시할 때** 새 내용으로 갱신됩니다.

공개 사이트에는 선택한 프로젝트의 역할, 문제, 실행, 성과, 배운 점, 태그, 링크와 사용자가 선택한 소개/연락 정보만 포함됩니다. 비공개 메모·자기분석·기업별 서류·면접 기록은 제외합니다. 프로젝트의 문제·실행 등 본문에도 민감한 내용을 쓰지 않도록 게시 전 미리보기로 확인해야 합니다.

초기 AI 공급자는 Groq이며 기본 모델은 `openai/gpt-oss-120b`입니다. `lib/ai-provider.ts`의 `AiProvider` 계약으로 다른 공급자를 추가할 수 있습니다. 모델은 `CAREERMAP_AI_MODEL`, 공급자는 `CAREERMAP_AI_PROVIDER`로 선택합니다. Groq 이외 공급자는 아직 구현하지 않았습니다.

자기점검은 직접 만든 자기성찰 질문이며, 검증된 심리·채용검사 또는 특정 기업의 적합도 판정이 아닙니다. 두 답변이 모두 모인 영역만 선호를 요약하고, 미응답을 중간 점수로 계산하지 않습니다. 상황 선택에는 정답·순위를 붙이지 않습니다. 분석 규칙은 결과 화면에서 확인할 수 있습니다. 질문 답변·이유·점검 기록은 공개 포트폴리오에 포함되지 않습니다.

새 경험 작성은 질문 3개로 시작합니다. 경험 설명만 있어도 AI 초안을 요청할 수 있습니다. 입력한 짧은 답변·보완 답변과 준비 유형·전공 배경·목표 직무만 해당 요청에 전달하며 비공개 메모·다른 프로젝트·기간·링크·이름·이메일은 기본 입력에서 제외합니다. 기존 경험을 AI로 다듬을 때는 제목·배경·역할·실행·결과·배운 점을 짧은 답변으로 가져오므로 전송 전 화면에서 확인하고 수정할 수 있습니다. AI가 입력 자료를 잘못 해석할 가능성은 있어 반영 전 검토가 필요합니다. 구조화 출력과 답변 근거 ID를 검증하고, 인용 답변에 없는 수치가 포함된 결과는 거부합니다. 태그는 답변에 실제로 적힌 이름만 사용합니다. 빈 항목을 기본 선택하며 기존 내용 교체는 직접 선택해야 합니다. 선택 반영은 편집기에만 적용되고 ‘경험 저장’을 눌러야 서버에 저장됩니다. 호출·저장 실패에도 작성 화면을 유지합니다.

마스터 자료는 공고 연결 없이 저장하며 기업별 자료와 독립적으로 복사할 수 있습니다. 서류 복사는 화면의 현재 초안을 먼저 저장하고 진행합니다. 마스터에는 제출본을 확정하지 않으며, 실제 공고의 복사본에서 제출본을 보관합니다.

첫 AI 사용 시 전달 자료를 안내하고 동의를 받습니다. 자기점검 AI 정리에는 선택한 질문·답변과 이유가 전달되며 프로젝트·서류·이름·이메일은 해당 작업에 전달하지 않습니다. 자기점검 답변은 다른 AI 작업에서 자동 전송되지 않습니다. 공통 면접 예상 질문에는 최대 3개의 마스터 서류를 각각 앞부분 3,000자까지 참고 자료로 전달합니다. AI 요청에는 준비 유형·목표 직무·배경, 선택한 경험, 공고/기업 자료 및 해당 작업의 서류·답변이 공급자에게 전달됩니다. 이름·이메일·비공개 메모는 기본 요청에서 제외합니다. 사용자가 본문에 직접 적은 개인 정보는 전송될 수 있습니다. 무료 API는 공급자 한도가 있으며, 앱도 사용자당 분당 3회/일일 40회 및 전체 분당 5회로 제한합니다. 429 응답을 처리하며 유료 모델로 자동 전환하지 않습니다. 합격 확률이나 보장된 적합도 점수를 만들지 않습니다. 프롬프트로 근거 없는 사실을 제한하지만, 모델이 기업 가치나 개인 배경·기간을 잘못 추정할 수 있습니다. 반영 전에 원본과 대조해 수정해야 합니다.

## 다음 단계

이 버전은 직접 사용하고 검토할 수 있는 MVP입니다. 공고 자동 수집·추천, 최신 기업 자료 검색, 음성·영상 면접, 포트폴리오 템플릿 선택은 후속 작업입니다. 현재 기업 분석은 사용자가 직접 입력한 자료를 근거로 하며 URL 본문을 자동으로 읽지 않습니다.

외부 출시 전에 이메일 인증·비밀번호 재설정·계정/데이터 삭제, 공유 서버용 인증 요청 제한, 개인정보 처리방침/AI 전송 동의, 백업·복구 및 운영 모니터링을 보완해야 합니다. HTTPS와 영구 저장소가 필요합니다. Vercel에서는 Turso DB를 사용하도록 구현했습니다. 로컬의 기존 데이터는 원격 DB로 자동 이관되지 않습니다. 현재 공개 URL은 `/p/[slug]`이며 커스텀 도메인과 개별 정적 사이트 내보내기는 포함하지 않습니다.

버전 관리는 날짜별 `daily/YYYY-MM-DD` 브랜치와 운영 `main`, 배포별 `release/YYYY-MM-DD.N` 태그를 사용합니다. [작업·배포 규칙](docs/GIT_WORKFLOW.md)과 [관리자 설정](docs/DEPLOYMENT.md)을 참고하세요. 브랜드는 이음(IEUM)이며, 기존 저장소·배포 주소·환경 변수·쿠키 이름은 기록 호환성을 위해 유지합니다.

제품 요구사항은 [PRD](docs/PRD.md), AI 도입 검토는 [AI 연동 문서](docs/AI_INTEGRATION.md)에 있습니다.
